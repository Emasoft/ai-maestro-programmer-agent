`scripts/publish.py` generates `CHANGELOG.md` via `run_git_cliff` and **auto-generates
`cliff.toml`** from a template string embedded in publish.py (the `[changelog].body`
Tera template). Two bugs lived here until **v1.4.4** (TRDD-3ff8013f):

**Bug 1 — the CHANGELOG silently collapsed to ONE version every release.** The
CHANGELOG-generation call used `git-cliff --bump --unreleased --tag vX.Y.Z -o
CHANGELOG.md`. `--unreleased` restricts output to commits **since the last tag**, and
`-o` **overwrites** the file — so every release rewrote `CHANGELOG.md` with only the
newest version's section. v1.3.0→v1.4.3 each shipped a single-section changelog, while
the docstring falsely claimed it walked "the full tag history". **Fix:** DROP
`--unreleased` from the CHANGELOG-generation call (`git-cliff --bump --tag vX.Y.Z -o
CHANGELOG.md` regenerates the COMPLETE history every release). **KEEP `--unreleased` on
the SECOND call** — the release-notes extraction (`--strip header`, →
`.git-cliff-release-notes.md`) legitimately wants latest-only.

**Bug 2 — the regenerated headings didn't render (CommonMark indented code blocks).**
The `body` Tera template embedded literal indentation: `{% if version %}    ## [...]`,
`    ### {{ group }}`, `        - ...{{ message }}    ` (4 spaces before `##`/`###`, 8
before `-`, 4 trailing). A 4-space-indented `##` is an indented code block, not a
heading. It was masked while Bug 1 kept the file to ~11 lines. **Fix:** de-indent the
template to flush-left `## [...]` / `### {{group}}` / `- {{message}}` with no trailing
whitespace — **in publish.py's generator (the One-Source-of-Truth), then regenerate
`cliff.toml` to match**, not just the on-disk `cliff.toml` (publish.py rewrites it at
publish time, so fixing only the file would re-break on the next release).[^1]

**Verify after any publish:** `grep -cE '^[[:space:]]+#' CHANGELOG.md` → 0 (no indented
headings), `grep -cE ' +$' CHANGELOG.md` → 0 (no trailing ws), `grep -cE '^## \[' CHANGELOG.md`
≥ the number of releases. Validated v1.4.4: 13 flush-left sections, CI green.

## Notes and lessons learned
[^1]: [ocd:2026-06-22 lmd:2026-06-22] The load-bearing trap: `cliff.toml` is
  auto-generated by publish.py, so a fix applied only to the `cliff.toml` FILE is
  reverted the next time publish.py runs. The template's single source of truth is the
  string inside `publish.py`; fix it THERE and regenerate. General lesson: when a config
  file carries an "auto-generated by X" header, the real edit site is X, not the file.
