## What actually changed, and what only looked like it

Ten items in the v2.1.233–v2.1.240 range touch a role plugin. **One** altered
something AMPA was asserting; one more added a fact worth writing down; the
remaining eight are new platform capabilities that need recording so the next
reader does not re-derive them.

The discipline that matters here is the one this repo learned twice already: the
dangerous changelog entry is never the one that errors. It is the one that
silently falsifies a claim an artifact is still making.

### A1 — v2.1.239, the UTF-8 BOM (Breaking, and silent)

An agent, skill, or command `.md` beginning with a UTF-8 BOM was **silently
ignored**: no error, no debug line the operator would look for, the artifact
simply never loaded. That is precisely the v2.1.218 and v2.1.232 defect class,
a third time.

AMPA ships no BOM today — verified by reading the first three bytes of every
tracked file, not by trusting an editor. The correction is therefore not a fix
but a **guard**, and the guard had to be built so it can actually fail: the
detection predicate takes bytes, and a control test feeds it synthetic
BOM-prefixed input to prove it reports. A test that passes only because the
defect is absent today is indistinguishable from a test that cannot fail, and
this file already says so in its own comments.

The byte-level detail is load-bearing and worth stating: reading these files as
decoded text hides the defect. `encoding="utf-8"` turns the BOM into an
invisible `U+FEFF`, and `utf-8-sig` strips it outright — both make a
BOM-prefixed file look clean. Only the raw bytes tell the truth.

### A2 — v2.1.234, the notification envelope

Background task notifications delivered *between* turns are now wrapped in
`<system-reminder>` tags, matching mid-turn delivery. On its own that is a
formatting note. It matters here because of what it wraps: since v2.1.232 a
delegated subagent's result reaches AMPA *as* that notification, which is the
whole basis of the collect-before-relay rule.

So the persona now records three things about the envelope, not one: it is
platform-generated context, it is **not** a message from the user, and it is
**not** the user approving something asked earlier. The third is the one worth
the ink — a notification landing while the agent waits on a human answer does
not supply that answer, and an agent that treats arrival as assent will act on
consent nobody gave.

## The guard that a naive bump would have broken

`tests/test_primary_skills.py` asserted the latest compatibility table with
`f"### v2.1.225 – {CLAUDE_CODE_ANCHOR} "`. That coupled the *start* of the
newest range to the start of the previous one — true only by accident, and
false at the first bump that opens a new range. Bumping the anchor alone would
have sent it hunting for `### v2.1.225 – v2.1.240`, a heading that must not
exist, because v2.1.225–v2.1.232 is a historical range that stays as written.

Fixed by giving the range start its own constant (`LATEST_TABLE_START`), so the
two ends of the heading move independently, as they actually do.
