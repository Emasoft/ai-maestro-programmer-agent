## Notes and lessons learned

Two coordinator errors, both caught by adversarial review before they reached
published text — recorded because the *shape* recurs, not the instances.

[^1]: DO NOT call a published claim false on the strength of a partial read. I read a
40-line window of a 600-line test file and concluded README's v2.1.239 row ("verified
by byte check over every tracked file … and a pytest guard now enforces that") was
false. It is not: the parenthetical scopes the one-time byte check, and the guard
clause reads as the shipped-artifact invariant. DO settle the whole surface first
(`grep -rn -i 'bom|utf-8-sig|xef' tests/ scripts/ .githooks/ .github/`), then add a NEW
row for the genuine gap instead of rewriting a defensible one. A wrong "correction" in
the compat section costs more than the gap it closes, because that section's whole
value is that its rows are trustworthy.

[^2]: DO NOT treat a symbol name found by grep as evidence that a test runs and passes.
A new guard's function name appeared in a mid-edit file that also carried a live
`json is not defined` diagnostic; had that been a module-level NameError, the file would
have failed collection and silently disabled the *pre-existing* BOM guard too — a broken
test file reports as coverage. DO run the suite yourself
(`uv run --with pytest --with pyyaml pytest tests/ -q`), never accept the authoring
worker's pasted output as proof. (Here the diagnostic was stale: `import json` is
function-local at the call site, matching the file's existing house pattern.)
